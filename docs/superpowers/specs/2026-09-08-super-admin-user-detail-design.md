# `/super-admin/users/[id]` — profile, 플로우 timeline, 행동(GA4) — design

**Date:** 2026-09-08 · **Status:** approved by the product owner · **Repo:** spot-admin (Next.js 16 / React 19 / OpenNext on Cloudflare Workers) · **Depends on:** backend PR `feat/admin-user-timeline` (`GET /admin/v2/users/:id/timeline`, `GET /admin/v2/users/:id/summary`) and the app PR that sends the `dopa_uid` user property; GA4 property must register the user-scoped custom dimension `dopa_uid`.

## Problem
There is no user detail page. `/super-admin/users` (generic `[section]` console) opens a right-side sheet with six fields from the list row. Operators need "이 사람의 플로우": a server-side activity timeline plus the user's in-app screen flow from GA4, side by side.

## Hard constraints (verified)
- `scripts/check-admin-runtime-boundaries.mjs` forbids Prisma, `DATABASE_URL`, Next `/api/(super-admin|business|party-categories)` routes and `@/lib/(api-auth|fetch-json|backend-internal|legacy-bff)`. Server data goes through `adminFetchJson` (`src/auth/api/admin-http.ts`) to the Worker; GA data is fetched in the browser from `https://analyticsdata.googleapis.com` (already in CSP `connect-src` in `src/lib/security-headers.ts:20` and `public/_headers`; GIS origins already in `script-src`/`frame-src`). No CSP change.
- Next.js route table is built from `page.tsx` files only. Adding `src/app/(super-admin)/super-admin/users/[id]/page.tsx` without `users/page.tsx` makes `/super-admin/users/<id>` resolve to the new page while `/super-admin/users` keeps resolving to `[section]/page.tsx` (static siblings `analytics/`, `dashboard/`, `mail/`, `reports/` already coexist with `[section]/`). Do **not** add `users/page.tsx`.
- Guards come from `src/app/(super-admin)/SuperAdminShell.tsx` (AuthGuard + RoleGuard SUPER_ADMIN_ONLY + AdminDesktopChrome). `AdminSidebar.isActiveRoute` prefix-matches, so `/super-admin/users/<id>` highlights "사용자" and `adminRouteLabel` returns "사용자" without changes.
- Existing deep links usable for timeline refs: `businessDetailPath(id)`, `businessPartyDetailPath(businessId, partyId)`, `/super-admin/payments?payments_q=<id>` / `?refunds_q=<id>`, `/super-admin/inquiries?q=<id>`. Reports have no per-id URL.
- Release-contract tests: `scripts/test-admin-ui-foundation.mjs` (asserts OPERATIONS.md documents GA4 setup incl. the phrase "브라우저 메모리", lazy chunks for heavy modules, no raw palette colors, no `text-[9|10|11px]`, no alpha focus rings, `zod/mini` only) and `scripts/test-public-ga4-config.mjs`. `npm run verify` = vitest + `node --test scripts/test-*.mjs` + runtime-boundary check + eslint + OpenNext build.
- `next/link` renders in jsdom without mocking; `next/navigation` is mocked per test via `vi.hoisted` (see `src/components/admin/AdminResourceConsole.test.tsx`).

## Routing / page module
`page.tsx` is a server component like `analytics/page.tsx`: `const { id } = await params; const config = parseAnalyticsProperties(process.env.NEXT_PUBLIC_GA4_PROPERTIES); return <UserDetailPage userId={id} analytics={{ properties: config.ok ? config.properties : [], configError: config.ok ? null : config.message, googleClientId: publicGoogleClientId() }} />` with `export const metadata = { title: "사용자 상세" }`. Type `params` as `Promise<{ id: string }>` (no `.next/types` dependency).

## Data layer
- `AdminApi` additions: `user(id)` → `/admin/v2/users/${encodeURIComponent(id)}`, `userTimeline(id)` → `…/timeline`, `userSummary(id)` → `…/summary`, `userBan(id)`/`userUnban(id)`; `ROUTE_SUPER_ADMIN_USERS = "/super-admin/users"`; `superAdminUserDetailPath(userId)`.
- `adminQueryKeys.users = { all: ["admin","users"], detail: (id) => ["admin","users","detail",id], summary: (id) => [...detail, "summary"], timeline: (id, filters = {}) => [...detail, "timeline", filters] }`. The list console uses `["admin-v2", "users", {...}]`; after ban/unban invalidate both.
- `src/auth/api/admin-users.api.ts` types (single source):

  Functions: `getAdminUser(id)` (normalizer tolerant of partial rows, like `normalizeParty` in `admin-party.api.ts`), `getAdminUserTimeline(id, params)` (query string: `kinds`/`categories` joined with `,`, `from`, `to`, `cursor` verbatim, `limit` default 20 — the backend caps at 50), `getAdminUserSummary(id)` (404 → `null`), `isAdminNotFound(error)` (`AdminAuthError && status === 404`). Backend shape drift is absorbed by the normalizers: accept both an inline `summary` on the detail and the separate route.
- Hooks: `useUserDetailQuery(userId)`; `useUserSummaryQuery(userId, { enabled })` (`retry: false`, `staleTime` 30 s); `useUserTimelineQuery(userId, filters)` = `useInfiniteQuery` with the cursor pattern from `AdminResourceConsole.tsx:136-147` (`initialPageParam: undefined`, `getNextPageParam: last => last.nextCursor ?? undefined`, `staleTime` 15 s, no `refetchInterval`).
- Error handling: `isAdminNotFound` → "사용자를 찾을 수 없습니다" + link back to the list (a 404 from the generic route while `/summary` succeeds means the user withdrew — render from the summary with a "탈퇴" badge); 403 → permission text; else the `ResourceError`-style block with 다시 시도.

Decision: single scroll, two columns at ≥ xl (correlating "결제 실패 21:14" with "21:13 /payment" is the page's value); no tabs.

- `UserDetailHeader.tsx`: back link `<Link href={ROUTE_SUPER_ADMIN_USERS}>← 사용자 목록</Link>` + breadcrumb `<nav aria-label="현재 위치">` "사용자 / {nickname}"; `Avatar` with `dopaMediaUrl(profileImage, { width: 80 })`; h1 nickname; `id` in `font-mono text-xs`; email; provider `Badge variant="outline"`; role/status via `renderResourceValue(value, "role"|"status")` (text badges, never color-only); `blocked` → Badge with `ShieldAlert` + "로그인 제한"; facts `<dl>` (tabular-nums): 가입, 수정, 평점, 마지막 활동 (`summary.profile.lastSeenAt`), 기기 (≤ 3: platform · appVersion), 활동 수 (label map over `counts`), 동의. "더 보기" + inline retry like `src/app/(super-admin)/super-admin/reports/page.tsx:317-351`, `useCursorAppendFocus` (append mode, `itemKeys = items.map(i => i.id)`).
