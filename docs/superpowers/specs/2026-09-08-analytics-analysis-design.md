# 제품 분석 고도화: 퍼널 · 리텐션 코호트 · 추세 차트 + 필터 · 인사이트 — design

**Date:** 2026-09-08 · **Status:** approved by the product owner · **Repo:** spot-admin · **Branch base:** `feat/super-admin-user-detail` head (reuses its extraction: `analytics-query-keys.ts`, `use-analytics-connection.ts`, `AnalyticsStates.tsx`, `analytics-labels.ts`, `dimensionFilter` support in `analytics-data-api.ts`, `dataQualityNoticesForReport` export).

## Problem
`/super-admin/analytics` has five GA4 views (개요/유입/참여/전환·매출/실시간) but no analysis: a CSS bar chart, no funnel, no retention, no filters, no summary. The product owner selected all four additions.

## Verified API facts
- Funnel: `POST https://analyticsdata.googleapis.com/v1alpha/properties/{id}:runFunnelReport`. `FunnelEventFilter.funnelParameterFilterExpression` → `FunnelParameterFilter { eventParameterName | itemParameterName, stringFilter | inListFilter | numericFilter | betweenFilter }` — event parameters like `firebase_screen`, `route`, `method`, `result` work **without** custom-dimension registration. `funnelFieldFilter` filters on standard dimensions. Response `{ funnelTable: FunnelSubReport, funnelVisualization: FunnelSubReport, propertyQuota, kind }`, `FunnelSubReport { dimensionHeaders, metricHeaders, rows, metadata { samplingMetadatas } }`; `dimensionHeaders[0]` is `funnelStepName` (values like `1. 파티 상세`), with breakdown the second header is the breakdown dimension and there are `RESERVED_TOTAL` rows; metrics `activeUsers`, `funnelStepCompletionRate`, `funnelStepAbandonments`, `funnelStepAbandonmentRate`. Funnel requests draw from a **separate Funnel quota pool** (same limits: 200k tokens/day, 40k/hour, 10 concurrent); `propertyQuota` in the response describes that pool.
- Cohorts: `runReport` with `cohortSpec`; `Cohort.dimension` supports only `firstSessionDate`; requests with `cohortSpec` must omit top-level `dateRanges`; WEEKLY offsets are ×7 days and cohort ranges should be Sunday–Saturday; `dimensionFilter` is allowed; metrics `cohortActiveUsers`, `cohortTotalUsers`; dimensions `cohort`, `cohortNthDay|Week|Month`. Core quota.
- Two `dateRanges` (named `current`/`previous`) in one `runReport` add an implicit trailing `dateRange` dimension to the response — `assertReportContract` (analytics-data-api.ts) must allow it when `request.dateRanges.length > 1`.
- `platform` values are exactly `"web" | "iOS" | "Android"` (verify against the 실시간 view before hard-coding chips).
- Trend metrics `active1DayUsers`/`active7DayUsers`/`active28DayUsers`, `newUsers`, `sessions` with dimension `date` are valid.
- `scripts/test-production-hardening.mjs:52-55` forbids `recharts` in dependencies ("stay deleted" guard). **Decision: no recharts.** The trend chart is a dependency-free inline SVG component.
- App instrumentation (Flutter): `screen_view` with `firebase_screen` = templated path (`/home`, `/parties/:id`, `/parties/:id/apply`, `/parties/:id/payment`, `/chat/rooms/:id`, `/my`, …; ids redacted to `:id`), `api_mutation { method (lowercase), route (templated: `/parties/:id/apply` after the app fix, `/parties/:id/:id` before it; `/payments/intent`, `/payments/confirm`), result (`success`|`failure`), status_group, failure_type }`, `login_started/login_completed/login_canceled/login_failed {provider}`, `signup_completed {provider}` (only new users, after `login_completed`), `logout_started/logout_completed`, `withdraw_started/withdraw_completed`, `banner_click`, `notification_opened`, `notification_permission {result}`, ad hoc `loading_stalled`, `chat_generation_mismatch`, `chat_realtime_recovered`; automatic `first_open`, `session_start`, `user_engagement`, `app_remove`, `os_update`, `app_update`; web `page_view`, `first_visit`, `app_cta_click {party_id, platform}`. User property `account_type` = `business|consumer` (register as user-scoped custom dimension for the filter). The route param may carry a `/v2` prefix depending on the Dio base URL — funnel route lists include both forms.

## Design

### 1. Data API client (`analytics-data-api.ts`)
- Add `AnalyticsCohortSpec`, `metricFilter?`, `cohortSpec?`; make `dateRanges` optional (cohort requests omit it); funnel request/response types (`AnalyticsRunFunnelReportRequest { dateRanges, funnel: { isOpenFunnel?, steps: [{ name, isDirectlyFollowedBy?, filterExpression }] }, funnelBreakdown?: { breakdownDimension: { name }, limit? (1–15, default 5) }, dimensionFilter?, limit?, returnPropertyQuota? }`, `AnalyticsFunnelFilterExpression` (andGroup | orGroup | notExpression | funnelEventFilter { eventName, funnelParameterFilterExpression? } | funnelFieldFilter), `AnalyticsFunnelParameterFilterExpression` with `funnelParameterFilter { eventParameterName | itemParameterName, …filters }`).
- Version routing: `ANALYTICS_DATA_API_ROOTS = { v1beta, v1alpha }`, `METHOD_VERSIONS = { runReport: 'v1beta', batchRunReports: 'v1beta', runRealtimeReport: 'v1beta', runFunnelReport: 'v1alpha' }`; `requestAnalyticsData`'s method union becomes `keyof typeof METHOD_VERSIONS`; URL = `${ROOTS[METHOD_VERSIONS[method]]}/properties/${id}:${method}`. Extract the fetch/retry/parse loop into `performAnalyticsRequest(url, init, schema, options)` so `getAnalyticsMetadata(propertyId, options)` (`GET ${v1beta}/properties/${id}/metadata`, zod/mini `looseObject` with `dimensions[{apiName, uiName?, customDefinition?}]`, `metrics[]`) shares the error taxonomy.
- `assertReportContract`: expected dimensions = request dims + `dateRange` when `dateRanges.length > 1`.
- Funnel schema (zod/mini only — the ui-foundation release test forbids `from "zod"`), `runAnalyticsFunnelReport(propertyId, request, options)`, `assertFunnelContract` (funnelTable present; `dimensionHeaders[0].name === "funnelStepName"`; breakdown header when requested; metric headers looked up by name; row value counts match headers).

### 2. Funnel
- `analytics-events.ts`: `APP_EVENTS` const + `EVENT_LABELS` (already corrected in PR5's `analytics-labels.ts` — merge into one module or re-export; single source).
- `funnel-definitions.ts`: helpers `eventStep(name, eventName)`, `screenStep(name, screen)` (= `screen_view` + `funnelParameterFilter { eventParameterName: "firebase_screen", stringFilter: { matchType: "EXACT", value } }`), `mutationStep(name, { routes, method, result })` (= `api_mutation` + andGroup[ route inListFilter, method EXACT, result EXACT ]). Presets (closed funnels):
  - `party-apply` 파티 신청: 파티 상세 `/parties/:id` → 신청 화면 `/parties/:id/apply` → 신청 완료 `mutationStep(routes: ["/parties/:id/apply", "/v2/parties/:id/apply", "/parties/:id/:id", "/v2/parties/:id/:id"], method: "post", result: "success")` (the `:id/:id` forms cover pre-fix app builds; comment as TODO to drop once ≥ 1.0.6 dominates).
  - `party-payment` 결제: 결제 화면 `/parties/:id/payment` → 결제 의도 `["/payments/intent", "/v2/payments/intent"]` post success → 결제 승인 `["/payments/confirm", "/v2/payments/confirm"]` post success.
  - `onboarding` 온보딩: `orGroup[first_open, first_visit]` → `login_started` → `login_completed` → `signup_completed`.
  - `buildFunnelRequest(definition, range, filters, breakdown)` → `{ dateRanges: [dateRange(range)], funnel: { steps }, funnelBreakdown: breakdown ? { breakdownDimension: { name: "platform" }, limit: 5 } : undefined, dimensionFilter: buildDimensionFilter(filters), returnPropertyQuota: true }`. Document that web `app_cta_click` → app `first_open` cannot be one funnel (different client ids across streams).
- `analytics-funnel.ts`: `fetchFunnel(input)` → one `runAnalyticsFunnelReport`; `shapeFunnel(response, definition, breakdown)`: parse `^(\d+)\. ` step prefix (fallback: appearance order); with breakdown, `RESERVED_TOTAL` rows are the main steps and other rows group by breakdown value; step `{ index, name, users, completionRate, abandonments, abandonmentRate, shareOfFirst }` (rates null on the last step). Shared numeric/row helpers move to `analytics-report-shaping.ts` (`numericValue`, `assertFiniteNumericString`, `reportRows`, `quotaFromReports`, `dataQualityNoticesForReport`). `isEmpty = steps.every(s => s.users === 0)`; quota tagged `category: "funnel"`.
- `AnalyticsFunnelResult = { view: "funnel"; funnelId; title; description; steps; breakdown: { dimension: "platform"; rows: Array<{ value; steps }> } | null; currencyCode; quota; dataQualityNotices; isEmpty }`.
- `FunnelPanel.tsx` (HTML/CSS): preset `<select aria-label="퍼널">`, "플랫폼별 보기" checkbox (both in the query key); per step: name, horizontal bar (width = shareOfFirst, `var(--chart-1)`, breakdown rows `--chart-2..5`), users (tabular-nums), "다음 단계 전환 xx.x%", "이탈 n명 (xx.x%)" as text next to the bar; empty copy "선택한 기간에 퍼널 1단계 이벤트가 없습니다. 앱 이벤트 수집과 라우트 템플릿을 확인해 주세요."; sampling notices via `DataQualityPanel`.

### 3. Retention
- `analytics-retention.ts`: `buildWeeklyCohorts(now, weeks = 6)` — last complete Sunday–Saturday week ending on/before yesterday, then 6 consecutive weeks back, names = startDate ISO (pure, `Date.UTC` on local Y/M/D; tests use `vi.setSystemTime`). `buildRetentionRequest(cohorts, filters, granularity = "WEEKLY")` → `{ dimensions: [cohort, cohortNthWeek], metrics: [cohortActiveUsers, cohortTotalUsers], cohortSpec: { cohorts: [{ name, dimension: "firstSessionDate", dateRange }], cohortsRange: { granularity: "WEEKLY", startOffset: 0, endOffset: 4 } }, dimensionFilter?, limit: 100, returnPropertyQuota: true }` — **no top-level dateRanges**; ≤ 30 rows, one Core request. `fetchRetention` uses the existing `runAnalyticsReport`. `shapeRetention(report, cohorts, yesterday)` → matrix keyed cohort × week, `rate = active/total` (null when total 0), cell `state` `complete | partial | future`; week 0 kept in data, hidden in UI. Result `{ view: "retention"; granularity: "WEEKLY"; horizon: 4; cohorts: [{ name, startDate, endDate, totalUsers, cells: [{ week, activeUsers, rate, state }] }]; currencyCode; quota; dataQualityNotices; isEmpty }`.
- `RetentionHeatmap.tsx`: semantic `<table>` (코호트 시작일 · 크기 · 1주..4주), `<td data-intensity={0..4} data-state>` with visible `xx.x%` text (never color-only), `†` + legend for partial, `—` for future; intensity via inline `--cell-alpha` and one literal class `bg-[color-mix(in_oklch,var(--chart-1)_calc(var(--cell-alpha)*100%),transparent)]`; 5-swatch legend; description "첫 세션 주 기준 주간 코호트 · GA4 firstSessionDate".

### 4. Trend chart + filters
- `charts/TrendChart.tsx` (default export, `"use client"`, **inline SVG, no dependency**): props `{ series: AnalyticsTrendSeries; metric: "activeUsers" | "newUsers" | "sessions"; showPrevious: boolean; width?: number }`; current period solid `var(--chart-1)`, previous dashed `var(--chart-2)`; x labels via `formatGaDate`; hover tooltip (both values); `<figure aria-label="일별 추세: {metricLabel}">` + sr-only `<table>` of the points; fixed `viewBox` with `preserveAspectRatio`, height 256. Lazy-loaded from the dashboard via `createRetryableLazyComponent` (release test asserts the dashboard does not statically import `./charts/TrendChart`). `TrendPanel` becomes metric toggle (aria-pressed) + "이전 기간 비교" checkbox + the chart.
- `fetchOverview`: requests 0/1 totals (+ dimensionFilter); request 2 = `dateRanges [current, previous]` (named) × `date` × `activeUsers,newUsers,sessions`, `orderBys date`, `limit 2 × RANGE_DAYS`; request 3 = same two ranges × `platform` × the same metrics, limit 20. Still one `batchRunReports`. Result gains `series` (missing dates zero-filled, previous aligned by index), `platforms[{ platform, current, previous }]`, `insights`; `trend` replaced by `series`.
- `analytics-filters.ts`: `AnalyticsFilters { platforms: readonly ("iOS"|"Android"|"web")[]; accountType: "all" | "consumer" | "business" }`, `EMPTY_FILTERS`, `filtersKey(filters)`, `buildDimensionFilter(filters)` (platform `inListFilter` ∧ `customUser:account_type` EXACT; single filter when one active; undefined when none), `availablePlatforms(property.platform)` (mixed → all three; others → none).
- Threading: `FetchAnalyticsReportInput.filters` → `coreRequest(range, dims, metrics, orderMetric, dimensionFilter)` → `definitionsForView(view, range, dimensionFilter)`, funnel, retention. **Realtime ignores filters** (filter bar shows "실시간 보고서에는 필터가 적용되지 않습니다").
- Capability: `fetchAnalyticsCapabilities({ propertyId, accessToken, signal })` in `analytics-reports.ts` via `getAnalyticsMetadata` → `{ accountTypeDimension: boolean; customDimensions: string[] }`; query key `["google-analytics", generation, propertyId, "capabilities"]`, `staleTime: Infinity`, `retry: false`. Account-type select disabled with hint "GA4 맞춤 정의에 사용자 속성 account_type을 등록하면 사용할 수 있습니다." when false.
- `AnalyticsFilterBar.tsx`: `role="group" aria-label="보고서 필터"`, platform toggles (aria-pressed), account-type `<select>` labelled "계정 유형", "필터 초기화", active count. Props `{ filters, onChange, platforms, accountTypeAvailability: "pending"|"available"|"unavailable"|"unknown", disabled }`.

### 5. Insights (`analytics-insights.ts`, pure)
`buildInsights({ metrics (current/previous totals), platforms, range }, thresholds = DEFAULT_INSIGHT_THRESHOLDS)` → `Insight[] { id; severity: "warning"|"positive"|"info"; text; metric; scope: "total"|"platform"; delta: number|null; current; previous }`. Rules: R1 totals (`activeUsers`, `newUsers`, `sessions`, `keyEvents`: previous ≥ 50 and |Δ%| ≥ 20 → "신규 사용자 32% 감소 (1,240 → 843)"; `engagementRate` |Δpp| ≥ 5 → "참여율 6.2%p 하락"; `totalRevenue` currency format, base ≥ 1); R2 platform (previous.activeUsers ≥ 30 and |Δ%| ≥ 25 → "Android 유입 급감 41% (활성 사용자 210 → 124)"); R3 platform share shift ≥ 10pp → info "iOS 비중 38% → 51%"; R4 one info when nothing fired and total previous users < 50 ("비교 기준이 작아 유의미한 변화를 판단하지 않았습니다"). Order: severity (warning, positive, info) → |delta| desc → metric asc → id asc; `slice(0, 5)`. `Intl.NumberFormat("ko-KR")`; percentages integer ≥ 10, one decimal below. Computed inside `fetchOverview` (no extra requests). `InsightsPanel.tsx`: `section aria-labelledby` "인사이트 요약", ≤ 5 `<li>` with severity icon + word badge ("주의"/"긍정"/"참고") + sentence + tabular-nums delta; empty → "이전 기간 대비 눈에 띄는 변화가 없습니다."

### 6. View wiring (`AnalyticsDashboard.tsx`, `types.ts`)
- `ANALYTICS_VIEWS = ["overview","acquisition","engagement","conversion-revenue","funnel","retention","realtime"]`; `AnalyticsReportResult` union += funnel/retention; `AnalyticsQuotaState.category: "core" | "realtime" | "funnel"`.
- State: `filters`, `funnelId` (default `party-apply`), `funnelBreakdown` (false), `trendMetric`, `showPrevious`. Date selector disabled for realtime **and** retention ("리텐션은 최근 6주 코호트 고정"). Query key `analyticsQueryKeys.report(generation, propertyId, view, range, filtersKey(filters), view === "funnel" ? `${funnelId}:${funnelBreakdown}` : "")`; React `key` on `AnalyticsQueryView` excludes filters so `placeholderData: keepPreviousData` keeps the previous table visible with `aria-busy` "필터 적용 중". `staleTime`/`gcTime`: realtime 60 s; overview/tables 5 min; funnel/retention 15 min.
- `fetchAnalyticsReport` dispatcher: funnel → `fetchFunnel`, retention → `fetchRetention`. `reportCompletionSummary`: funnel "단계 n개, 1단계 사용자 m명"; retention "코호트 n개". Empty-state copy per view.
- Quota UX: `analytics-quota.ts` `quotaPressure(quota) → { level: "ok"|"low"|"exhausted", … }` (low when remaining < 10% for hour or day); `QuotaBanner` above the tabs reading the latest cached result for the property ("GA API 시간당 할당량이 10% 미만입니다. 퍼널·리텐션은 토큰을 많이 소비합니다."); `QuotaFooter` shows pool labels (Core / 실시간 / 퍼널(별도 풀)). Tabs disabled only after an actual quota error for that pool.
- `AnalyticsDashboard.test.tsx` mocks `./analytics-reports` with `{ fetchAnalyticsReport }` only — extend the mock with every new named import (`fetchAnalyticsCapabilities`, …) and mock `./charts/TrendChart` with a stub.
